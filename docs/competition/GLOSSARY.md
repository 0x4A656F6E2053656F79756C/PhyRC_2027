# 처음 참가하는 팀을 위한 용어·숫자 안내

## `(2,9)`는 무엇인가요?

괄호 안 숫자는 **배열의 크기(shape)**입니다. `(2,9)`는 **2행 × 9열**입니다.
이 환경의 action에서는 2행이 로봇 2대,9열이 로봇 한 대의 명령 9개에 해당합니다.
총 18개의 명령을 두 로봇별로 나누어 담습니다.

```text
행0 = robot_0: [전진, 왼쪽, 베이스회전, 리프트, 팔신장, 손목yaw, 손목pitch, 손목roll, 그리퍼]
행1 = robot_1: [전진, 왼쪽, 베이스회전, 리프트, 팔신장, 손목yaw, 손목pitch, 손목roll, 그리퍼]
```

Python의 행/열 인덱스는 0부터 시작합니다.

```python
import numpy as np

action = np.zeros((2, 9), dtype=np.float32)
action[0, 3] = 1.0   # robot_0의 리프트 상승 명령
action[1, 8] = -1.0  # robot_1의 그리퍼 열기 요청
```

다른 값은 0입니다. 이동·회전 0은 해당 구동 명령이 없다는 뜻이며, 측정된 속도가 즉시 0이 된다는 뜻은 아닙니다.
그리퍼 0은 이전 개폐 의도를 유지합니다.

## `−1,0,1`은 속도인가요?

명령 크기를 공통 범위로 표현한 **정규화 값**입니다. 측정된 속도나 관절 각도가 아닙니다.

| 값 | 이동·회전에서 | 그리퍼에서 |
|---|---|---|
| +1 | 설정된 명령 스케일의 100%, 양의 방향 | 닫기 요청 |
| 0 | 해당 축에 구동 명령 없음 | 이전 개폐 의도 유지 |
| −1 | 설정된 명령 스케일의 100%, 음의 방향 | 열기 요청 |
| +0.3 | 설정된 명령 스케일의 30%, 양의 방향 | 그리퍼는 별도 임계값을 사용하므로 의도 유지 |

키보드는 방향 키를 누르거나 떼므로 주로 −1,0,1이 저장됩니다. 학습한 정책은 그 사이 소수도 출력할 수 있습니다.
예를 들어 리프트 명령 스케일이 1.54m/s일 때 `action[0,3] = 0.1`은 0.154m/s를 요청합니다.
실제 로봇 속도는 가속·관절 제한·물리 반응을 거친 **관측값**에서 확인합니다.
그리퍼는 >0.5 닫기, <−0.5 열기이며 사이 값은 이전 의도 유지입니다.

## 다른 배열 표기도 읽어보기

| 표기 | 읽는 방법 | 이 환경의 예시 |
|---|---|---|
| `(2,9)` | 2행, 각 행 9개 값 | 두 로봇에 보낼 action |
| `(18,)` | 길이 18인 한 줄 목록 | 위 두 행을 이어 붙인 저장 action. 쉼표는 1차원 표기 |
| `(N,18)` | N개 시점, 시점마다 18개 값 | HDF5의 actions. 예제 N=1,142 |
| `(2,13)` | 로봇 2대, 로봇마다 13개 관절 값 | joint_position / joint_velocity |
| `(2,7)` | 로봇 2대, 로봇마다 자세 7개 값 | 위치 3개 + 방향 4개 |
| `(5,256,256,3)` | 카메라 5개, 높이 256, 너비 256, 색상 3개 | RGB 이미지 |
| `(5,256,256,1)` | 같은 5개 이미지, 픽셀당 값 1개 | depth 또는 depth_valid |
| scalar | 숫자 하나 | simulation_time_s |

여기서 카메라 5개는 외부 1개 + 로봇 0 손목/상단 2개 + 로봇 1 손목/상단 2개입니다.
HDF5는 카메라별 키로 나눠 저장하므로 `overview_rgb` 한 장의 크기는 `(256,256,3)`입니다.
비영상 배열을 CSV/HDF5에 펼칠 때는 robot_0의 값을 모두 쓴 다음 robot_1의 값을 씁니다.
`joint_position[13]`은 펼쳐 저장한 배열의 14번째 값, 즉 robot_1의 첫 관절입니다.

### 관절은 13개인데 명령은 왜 9개인가요?

관절 상태는 로봇 안의 관절을 각각 측정한 값입니다. 명령은 사람이 조종하거나 정책이 제어할 기능 단위입니다.
예를 들어 팔 신장 명령 하나로 여러 팔 관절을 함께 움직이고, 그리퍼 개폐 명령 하나로 양쪽 손가락을 제어합니다.
그래서 관측의 관절 개수와 action의 명령 개수가 같을 필요는 없습니다.

`controller_target`도 크기가 `(2,9)`이지만 action과는 열 순서·단위가 다릅니다.
이 값은 내부 제어기의 현재 위치·속도 목표이고, action은 다음 구간에 보낼 정규화 명령입니다.
각 열은 [데이터 가이드](DATA.md#공개-observation-필드와-좌표계)의 정의를 따르세요.

## 관측, 액션, 정책, 에피소드

| 용어 | 뜻 |
|---|---|
| GUI / headless | 시뮬레이션 창을 띄워 실행 / 창 없이 실행. headless에서도 물리 계산과 카메라 렌더링이 가능 |
| viewport | Isaac Sim 창에서 3D 장면이 보이는 영역. 조종 전 이 영역을 클릭해 키보드 초점을 둠 |
| teleop | 사람이 키보드로 로봇을 직접 조종하는 것 |
| demonstration / 시연 | 사람이 보여준 조작의 기록. 성공·실패 시연 모두 생길 수 있음 |
| policy / 정책 | 현재 허용 관측을 보고 다음 로봇 명령을 결정하는 모델/함수 |
| observation / obs / 관측 | 카메라 영상과 로봇 위치·속도처럼 정책에 주어지는 입력 |
| action / 액션 | 다음 구간에 로봇이 수행하도록 정책 또는 사람이 요청한 명령 |
| next_obs | 그 action을 적용한 뒤 얻은 관측 |
| proprioception | 카메라 외에 로봇이 자신의 관절·베이스 등의 상태를 표현한 관측 |
| episode / 에피소드 | 시작부터 종료/초기화까지 이어진 한 번의 시도 |
| transition / 전이·학습 구간 | obs → action → next_obs 한 묶음. 이 환경에서는 0.05시뮬레이션초 |
| randomization / 무작위 초기화 | 시도마다 정해진 범위에서 초기 배치 등을 다르게 구성하는 것 |
| seed / 시드 | 무작위 초기화에 쓰는 번호. 같은 버전·설정에서 초기 배치를 다시 선택하는 데 사용하며, 다른 PC의 물리 결과까지 동일하게 보장하지는 않음 |
| inference / 추론 | 학습된 정책으로 다음 action을 계산하는 것 |
| rollout | 정책을 환경에서 실행하여 한 번의 시도를 진행하는 것 |
| checkpoint | 저장된 모델 가중치. 로봇 장면 상태를 저장한 슬롯과 다름 |

같은 에피소드에서 `next_obs[t]`는 다음 행의 `obs[t+1]`과 같습니다.
따라서 action 구간이 N개이면 고유한 관측 시점은 N+1개입니다.
초기화로 에피소드가 바뀌면 이전 에피소드 마지막 관측과 다음 에피소드 첫 관측을 이어 붙이지 않습니다.

## 시간: 20Hz, 60Hz, 240Hz와 tick

- **20Hz 정책**: 시뮬레이션 1초에 20번 명령을 선택합니다. 한 명령은 0.05초 유지합니다.
- **60Hz 제어**: 그동안 내부 제어가 3번 동작합니다.
- **240Hz 물리**: 그동안 물리 계산이 12번 동작합니다. 물리 계산 1회를 tick이라고 부릅니다.

PC가 느리면 시뮬레이션 0.05초를 계산하는 데 실제 0.5초가 걸릴 수도 있습니다.
데이터 타임스탬프와 점수 계산은 시뮬레이션 시간을 사용합니다.
MP4의 fps(재생 1초당 영상 프레임 수), 기록의 20Hz, 물리의 240Hz는 서로 다른 숫자입니다.
5fps 열람 영상은 일부 이미지만 보여주는 사본이며 원본 학습 데이터의 20Hz를 바꾸지 않습니다.

## 위치·방향·이미지 숫자

| 용어 | 뜻과 해석 |
|---|---|
| world 좌표계 | 장면 전체에 고정된 기준. Z가 위쪽 |
| base 좌표계 | 해당 로봇 베이스를 기준으로 한 값. 로봇이 움직이면 기준도 움직임 |
| pose / 자세 | 위치와 방향의 묶음. 이 환경의 7개 값은 x,y,z,qw,qx,qy,qz |
| quaternion / 쿼터니언 | 방향을 표현하는 4개 값. w,x,y,z 순서이며 각각을 각도로 읽으면 안 됨 |
| yaw / pitch / roll | 서로 다른 회전축의 관절 회전. 실제 키/양의 방향은 액션 명세를 따름 |
| m / rad | 미터 / 라디안. 약 3.14159rad가 180도 |
| twist | 선속도 3개와 각속도 3개. 위치/각도 자체와 다름 |
| egocentric / 로봇 시점 | 로봇에 부착된 손목·상단 카메라의 시점 |
| overview / 외부 시점 | 로봇 밖에서 장면을 보는 허용된 외부 카메라의 시점 |
| RGB-D | 색상(RGB)과 깊이(depth)를 함께 제공하는 관측 |
| RGB | 픽셀당 빨강·초록·파랑 3개 값 |
| depth | 픽셀의 카메라 광학 Z 깊이(m). 밝기값과 다름 |
| depth_valid / mask | 그 픽셀의 깊이값을 사용할 수 있는지 나타내는 true/false |
| uint8 | 0–255 정수. RGB에 사용 |
| float32 / float64 | 소수를 표현하는 32/64비트 숫자. 타입 자체가 m/s 같은 물리 단위를 정하지는 않음 |
| bool | true/false 두 값. CSV에서 1/0으로 보일 수도 있음 |
| dtype | 배열 숫자의 저장 형식. uint8, float32, bool 등이 해당 |
| HWC / CHW | 이미지 배열의 높이·너비·채널 순서 / 채널·높이·너비 순서 |

무효 depth는 0이고 mask=false입니다. 깊이 0을 카메라 바로 앞의 물체로 처리하지 않도록 mask를 사용하세요.
그리퍼의 `gripper_close_command=true`는 닫으라는 의도이며, 실제로 천을 잡았다는 정답이 아닙니다.

## 파일과 점수

명령의 `--training-record 1`은 학습 기록 기능을 켠다는 뜻이며 `0`은 끈다는 뜻입니다.
`--evaluate 1`도 같은 방식으로 자동 평가를 켭니다. 옵션 값 1은 기록할 시연 개수나 배속이 아닙니다.
문서의 `<실행ID>`는 실제 생성된 폴더 이름으로 바꾸어 입력할 자리입니다.

| 용어 | 뜻 |
|---|---|
| HDF5 | 여러 배열을 폴더처럼 묶은 학습 데이터 파일. policy.hdf5가 공개 학습 데이터 |
| CSV | 표 형태의 텍스트. Excel/LibreOffice에서 열어 숫자를 볼 수 있음 |
| audit / 감사 데이터 | 재현·동기화·점수를 확인하는 자료. 정책 입력으로 쓰는 파일이 아님 |
| raw archive | 물리 tick별 원본 상태·입력 기록. 재생/검증용이며 정답 정책으로 재생하면 안 됨 |
| deferred / 종료 후 변환 | 조종 중 상태를 저장하고 ESC 후 이미지를 만드는 기본 수집 방식 |
| READY | 이미지와 학습 파일 생성이 완료됐다는 터미널 표시 |
| reward | 학습용 보상 필드. 현재 수집 파일에서는 기본 0이며 평가 점수와 다름 |
| done | 에피소드 종료 표시. 착의 성공 표시가 아님 |
| raw_points | 집기를 포함한 누적 총점, 최대 50 |
| rate_points | 집기를 제외한 points/s 분자, 최대 45 |
| points/s | 집기 제외 점수를 최초 접촉~마지막 착의 득점 시간으로 나눈 값 |
| success | 평가기의 착의 성공 조건을 달성했는지 나타내는 값 |

**ESC는 조종 종료이고 READY는 파일 생성 완료입니다.** ESC 후 터미널을 닫지 말고 READY까지 기다리세요.
